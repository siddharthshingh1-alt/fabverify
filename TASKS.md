### ACCOUNT SECURITY & RECOVERY (recorded 2026-07-29 — build in Phase A AFTER the current security batch + issue B)
> **The gap:** if someone obtains a user's OTP (stolen or unlocked phone, shoulder-surfing) and logs in, the real owner has almost no recourse today — they cannot see active sessions, cannot remotely log out an intruder, get no login alert, and sensitive actions never re-authenticate. **Priority: low-to-medium.** The attacker bar is higher than a remote exploit (it needs physical access to the phone or the OTP), but this matters for real user trust — a marketplace that moves money must let an owner reclaim their account. Related: DECISIONS **M10** (password login, decided but not built), the missing desktop sign-out, and **issue B** (chat sign-out does not end the session).

- [ ] **Active session visibility + remote logout.** Let a user see their signed-in devices and "log out other devices".
- [ ] **New-device login alert.** Notify the owner when their account is signed into from a new device, so an intruder login is noticed rather than silent.
- [ ] **Re-authentication for sensitive actions.** Require a fresh OTP (or password) to move money, change the registered phone, or delete data — even inside an already-logged-in session. A stolen session should not be able to drain or hijack an account without a second proof.
- [ ] **Account recovery.** Let the real owner prove ownership and forcibly terminate all other sessions.
- [ ] **Password (M10) as a second factor**, so a stolen OTP alone is not enough to take an account.

**⚠️ Technical prerequisite — sequencing matters.** "Log out other devices" and per-session visibility need a durable link between a `users` row and its auth identity. That link does not exist yet: `users.id` is a generated UUID that never equals `auth.uid()`, which is exactly why RLS is decorative today (**DECISIONS I7**) and why phone reassignment is unresolved (**I6**). The likely fix for both is the `users.auth_user_id` column noted in I6. Supabase's `signOut({ scope: 'global' })` revokes every refresh token for an auth user and is the probable mechanism for "log out everywhere" — but it can only be aimed correctly once that column exists. **Do I6's durable auth link first, or this group cannot be built properly.**
